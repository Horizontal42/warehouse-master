# Warehouse Master

> Специализированная WMS-система сервисного центра: автоматизация складского учёта, алгоритмическое грейдирование электроники и потоковая печать термоэтикеток.

Warehouse Master — десктопный программный комплекс класса WMS (Warehouse Management System), спроектированный для сервисных центров, цехов сборки и участков предпродажной подготовки (refurbishment) компьютерной техники. Система решает задачи сквозного партионного учета комплектующих, автоматизирует процесс многофакторного грейдирования техники (присвоение товарных категорий NEW, A, B, C, D), обеспечивает высокоскоростную потоковую генерацию нумерованных термоэтикеток со штрихкодами через ReportLab и синхронизирует состояние склада с облачной базой данных в Google Sheets API.

Внедрение комплекса исключает ошибки ручного сопоставления запчастей, ускоряет сборку и комплектацию готовых изделий, а также обеспечивает прозрачную историю перемещения и списания номенклатуры.

## Ключевой функционал

### 1. Алгоритмический модуль грейдирования техники (NEW / A / B / C / D)
Автоматизирует объективную оценку косметического и технического состояния собираемых устройств на основе взвешенного анализа состояния узлов:
- **Оценка корпусных и внешних элементов**: проверка состояния крышки матрицы (A), рамки экрана (B), топкейса/палмреста (C1/C2), нижней крышки (D), клавиатурного блока, тачпада и сенсора матрицы.
- **Аппаратные лимиты телеметрии**: сопоставление выработки накопителя SSD (часы работы, процент ресурса) и износа батареи (счетчик циклов заряд-разряд).
- **Матрица грейдов**:
  - **NEW (Идеальное)**: максимальный ранг всех корпусных узлов и матрицы (5/5), наработка аккумулятора `< 150` циклов, отсутствие эксплуатационных следов.
  - **Grade A (Отличное)**: минимальные следы эксплуатации, безупречные конструктивные элементы, ресурс SSD классов A/B.
  - **Grade B (Стандартное рабочее)**: умеренные косметические дефекты без нарушения функциональности, SSD класс B.
  - **Grade C (Удовлетворительное)**: выраженные следы эксплуатации или затертости корпусных элементов.
  - **Grade D (Утилизация / Дефект)**: наличие критического дефекта хотя бы одного ключевого узла (ранг ≤ 1).

### 2. Потоковая генерация и прямая печать этикеток (ReportLab)
Векторный генератор макетов, оптимизированный под промышленные термопринтеры рулонной и листовой печати:
- **Точная векторная верстка**: субмиллиметровое позиционирование меток и типографики на базе шрифта `Inter`.
- **Промышленные форматы**:
  - **Single (рулон)**: `58 × 40 мм` альбомная ориентация (стандарт термоэтикеток для принтеров Zebra, TSC, Godex, Xprinter).
  - **Сетка 2 × 2**: `58 × 40 мм` (4 компактные номерные этикетки на стикер).
  - **Сетка 4 × 4**: `120 × 75 мм` (16 стикеров на форматный лист).
- **Диапазонная сериализация**: автоматическая развёртка числовых диапазонов (например, `1000–1250`), пакетная обработка нескольких серий за один проход и генерация компактного многостраничного PDF.
- **Интеграция с диспетчером печати Windows (`win32print`)**: отправка задания в очередь печати термопринтера в один клик без вызова внешних диалоговых окон с автоматической очисткой временных файлов.

### 3. Синхронизация с облачным складом (Google Sheets WMS)
- **Атомарная привязка комплектующих**: сопоставление ID установленных деталей (материнские платы, матрицы, клавиатуры, SSD, АКБ) с серийным номером ноутбука.
- **Сквозное списание номенклатуры**: поиск позиций через API библиотеки `gspread`, перевод установленных запчастей из статуса «В наличии» в «Отгружен», освобождение виртуальных ячеек хранения и запись обновленного грейда в сводную ведомость.
- **Журналирование и интеграция с ERP**: формирование готовых текстовых комментариев к наряду, технологических карт операций и списков установленных комплектующих для быстрой вставки в корпоративную ERP/CRM.

### 4. Эргономика и локализация
- **Контрастные цветовые схемы**: Темная и Светлая темы оформления интерфейса для комфортной работы в условиях складского или цехового освещения.
- **Защита от случайного скролла**: специализированные контролы (`NoScrollComboBox`), блокирующие случайное изменение выбранных параметров при прокрутке колесом мыши.
- **Полная двуязычность**: мгновенное переключение интерфейса между русским и английским языками на лету.

## Системные требования

- **ОС**: Windows 10/11, macOS 11+, Linux (Ubuntu 20.04+)
- **Python**: 3.10+
- **Оборудование**: Любой совместимый с Windows термопринтер этикеток (Zebra, TSC, Godex, Xprinter, Citizen, Brother) либо офисный принтер.

## Установка и запуск

### 1. Подготовка окружения

```bash
git clone https://github.com/Horizontal42/warehouse-master.git
cd warehouse-master
pip install -r requirements.txt
```

### 2. Конфигурация Google Cloud API

1. В панели Google Cloud Console активируйте **Google Sheets API**.
2. Создайте учетные данные типа **OAuth 2.0 Desktop Client ID** и скачайте файл конфигурации.
3. Разместите `credentials.json` в папке программы либо в `%APPDATA%/WarehouseMaster/credentials.json`:

```bash
cp credentials.example.json credentials.json
```

4. Скопируйте и настройте структуру таблиц склада:

```bash
cp sheet_config.example.json sheet_config.json
```

### 3. Запуск и настройки

```bash
python main.py
```

В меню **Settings** укажите:
- URL рабочей таблицы Google Sheets;
- Цветовую тему и язык интерфейса;
- Каталог для сохранения сгенерированных PDF-файлов.

## Сборка бинарного дистрибутива

Для формирования автономного исполняемого файла Windows:

```bash
pyinstaller WarehouseMaster.spec
```

Скомпилированный файл будет доступен в папке `dist/WarehouseMaster.exe`.

## Безопасность и хранение ключей

- **Исключение приватных данных**: Рабочие файлы авторизации (`credentials.json`, `token.json`, `service_key.json`) и локальные конфигурации добавлены в `.gitignore` и защищены от попадания в историю контроля версий.
- **Локальное хранение сессий**: Токены пользовательских сессий OAuth кэшируются исключительно локально в каталоге пользователя `%APPDATA%/WarehouseMaster/`.
